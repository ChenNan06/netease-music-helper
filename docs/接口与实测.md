## 1. 请求层

所有业务接口走 **weapi**：把 `/api/xxx` 换成 `/weapi/xxx`，POST 表单
`params=<AES 密文>&encSecKey=<RSA 密文>`，query 带 `csrf_token`（取自 cookie）。

| 环节 | 实现 | 说明 |
|---|---|---|
| 内层加密 | AES-128-CBC，key `0CoJUm6Qyw8W8jud`，iv `0102030405060708` | 预设密钥，前端硬编码值 |
| 外层加密 | AES-128-CBC，key = 16 位随机 base62 | 每次请求换一次 |
| 密钥加密 | RSA-1024 **裸模幂**（无填充），输入是随机 key **反转**后的 16 字节 | 等价于 forge 的 `encrypt(str,'NONE')` |
| 实现 | `crypto.subtle`（AES）+ 自写 BigInt 模幂（RSA） | 零外部依赖；`--net` 测试证明服务器接受 |

> 实测：`/weapi/v3/song/detail` → HTTP 200 / `code=200` / 返回「晴天」；`/weapi/song/lyric/v1` → `code=200` 且 lrc 含时间戳。
> 若加密写错，服务器会返回 `code=-460`（"Cheating"）。本实现 0 次 `-460`。

**请求身份**（设置可切）：

| 身份 | UA | 附加 cookie | 用途 |
|---|---|---|---|
| `web`（默认） | Chrome UA | 无（用页面登录态） | 最稳，和网页行为一致 |
| `pc` | `NeteaseMusicDesktop/3.1.22` | `os=pc;appver=…` | 个别曲目音质更好 |
| `android` | `NeteaseMusic/9.1.78` | `os=android;appver=…` | 同上 |

### 搜索为什么要两个接口

匿名态（以及风控触发时）`cloudsearch` 返回 `code=50000005` 且 `result` 为空。
原 B 脚本只用 cloudsearch，于是**未登录时搜不出歌**。现在：

```
cloudsearch → 没结果？→ 自动改用 search/get/web → 再补一次 v3/song/detail 拿音质字段
```

## 4. 云盘快传的真实链路

```
① 取指纹：/song/enhance/download/url/v1（优先，带 md5/size/br/type）
          ↓ 拿不到就退
          /song/enhance/player/url/v1
② 检查：  /api/cloud/upload/check/v2  → data[0].upload
          = 0 → 服务器已有同 md5 文件（直接算成功）
          = 1 → 需要"认领"
          其他 → 该文件不可快传
③ 导入：  /api/cloud/user/song/import → data.successSongs[0].song.songId（云盘 id）
④ 匹配：  /api/cloud/user/song/match {songId: 云盘id, adjustSongId: 曲库id}
```

**为什么叫"快传"**：第 ②③ 步只提交 **md5 + 文件元信息**，不传一个字节音频。
服务器若已有同 md5 的资源，就直接把这个资源挂到你的云盘 —— 秒完成、不占带宽。
这也是原脚本最能打的功能，逻辑原样保留。

> 提醒：`check` 返回 `code=-460` 时通常是**未登录**或请求被风控。UI 会提示"需要登录"。

## 5. 错误码对照（脚本里已处理）

| code / 现象 | 含义 | 脚本行为 |
|---|---|---|
| `200` | 正常 | 继续 |
| `301` / `250` | 未登录 | 云盘页提示"需要登录网易云后才能读取云盘" |
| `-460` | 风控 / 参数非法 | 快传判失败并提示；日志里记录完整返回 |
| `50000005` | 搜索接口风控 | 自动降级到旧搜索接口 |
| `data.url=null` | 该音质无权限 | 触发降档 / 换方法；全失败则报"所有取链方式均未取到地址" |
| HTTP 非 200 | 网络 / 服务异常 | 按设置重试 N 次，仍失败则记录 `tried` 明细 |

## 7. 媒体 CDN 实测：为什么"网络错误"不是服务器的问题
用户第一版报障里，封面与音频都报 `网络错误: unknown`。逐项实测（2026-11-25）：

| 检查 | 结果 |
|---|---|
| `HEAD https://p2.music.126.net/...jpg?param=500y500` | **200**，`content-type: image/jpg`，`content-length: 40355` |
| 同上 + `Referer: https://music.163.com/` | **200** |
| 同上 + 走 Clash 代理 | **200** |
| 同上带 `Origin` 看 CORS | `Access-Control-Allow-Origin: *`、`Allow-Methods: GET,POST,OPTIONS`、`Allow-Credentials: true` |
| `HEAD http://m704.music.126.net/...mp3` | **200** |
| 同一路径改 `https://` | **200** |

**结论**：服务器与 CDN 都正常，失败发生在客户端 —— 脚本管理器/浏览器把请求拦了（最典型是 `@connect` 白名单、或 https 页面里的 http 混合内容）。
而旧代码的 `onerror` 只写 `res.status`，把管理器给的真实原因（`error`/`errorText`）丢了，所以日志里只剩 `unknown`。

因此 v1.0.1 的取字节改成三通道（任何一条成功即止），并且**把失败原因原样带出来**：

| 通道 | 做法 | 何时最有效 |
|---|---|---|
| ① GM | `GM_xmlhttpRequest({responseType:'arraybuffer'})` | `@connect` 已放行时（最快，可带客户端头） |
| ② fetch | 页面内 `fetch(url, {credentials:'omit', mode:'cors'})` | CDN 带 `ACAO: *`（网易云 CDN 实测都带）→ 完全绕开管理器白名单 |
| ③ GM 匿名 | 同 ①，但 `anonymous:true` | 某些管理器在带 cookie 时才拦跨域请求 |

另外两条硬规则：

- **`http://` 媒体地址一律升 `https://`**（`*.126.net` 两种协议都实测 200），避免 https 页面的混合内容拦截；
- 三条通道全失败时**降级为直链下载**（`GM_download` → 页面内 `<a download>`），只丢"写标签"，不丢文件。

## 8. 登录 vs 匿名：音频档位的真实边界（2026-11-25，VIP 账号实测）

用同一首歌、只改 Cookie，跑出来的结论（明细见 `logs/identity-matrix.json`、`logs/vip-matrix.json`）：

| 请求档位 | 匿名 | 登录（vipType 110） |
|---|---|---|
| `jymaster` 超清母带 | 方法①`code 301` / 方法②`exhigh` 或空 | **`jyeffect` 沉浸声 108.6MB**（服务端降档） |
| `hires` 高解析 | 同上 | `hires` 63MB |
| `lossless` 无损 | 同上 | `lossless` 35.8MB |
| `exhigh` 极高 | 方法②直接给（免费曲目） | `exhigh` 11.3MB |

**四条结论（已写进代码逻辑）**：

1. **方法① `/song/enhance/download/url/v1` 匿名恒返回 `code 301`** → 本机判定"未登录"时**直接跳过**这一路，省一次请求；
2. **服务端会降档返回**（要母带给沉浸声）→ 产品必须展示 `data[0].level`，不能拿请求值冒充；
3. **VIP 曲目（`fee=1/8`）匿名两路全空**，登录后才给地址；
4. **`plLevel:none` + `st:-200` = 已下架/无版权** → 这种歌谁都拿不到，**不能拿它当测试样本**（《晴天》id 186016 就是这种，我第一次误判成"登录无效"）。

### 请求身份的实验结论

| Cookie 组合 | 结果 |
|---|---|
| 只带 `MUSIC_U` | 与带 `MUSIC_U + __csrf` **完全一致** |
| 再加 `os=pc; appver=8.9.70; channel=netease` | 无变化（不会让权限变好，也不会变差） |
| 只带 `MUSIC_U` + PC UA（`NeteaseMusicDesktop/3.1.22`） | 无变化 |

结论：**web 身份（默认）就够**，不必为了"更高音质"去伪装客户端；伪装只在个别曲目上有差别，但会引入 UA 与 cookie 不一致的风险。

## 9. /api/cloud/del 的参数名（2026-11-25 实测，踩坑记录）

| 传参 | 返回 |
|---|---|
| { ids: JSON.stringify([1]) } | 400 {"code":400,"message":"参数错误"} |
| { id: 1 } / { id: [1] } / { id: "1" } | 同样 400 参数错误 |
| { songIds: [1] } | **{"succIds":[],"failIds":[1],"code":404}** ← 服务端认这个参数名 |

结论：

- 参数名是 **songIds**（数组，不是 JSON 字符串）；
- 返回结构是 { code, succIds: [], failIds: [] } —— **部分成功时不一定 200**，所以要按 succIds 判定，别只看 code === 200；
- 用不存在的 id（1）试探是安全的：它只会回 ailIds:[1]，不会误删任何文件（探完复查云盘数量没变）。
