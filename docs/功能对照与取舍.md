# 功能对照与取舍

> 两个原脚本的功能逐条对照：**留什么、怎么合、删什么、为什么**。
> 原脚本留档在 `downloads\`（`ncm-helper-531392.user.js` 586 行 / `ncm-download-459633.user.js` 9490 行）。

---

## 0. 两个脚本的定位差异（决定了怎么合）

| | A：网易云音乐助手 v2.1（RunningCheese） | B：歌曲下载&转存云盘 v4.4.6（cinvin） |
|---|---|---|
| 体量 | 586 行 / 23 KB | 9490 行 / 396 KB |
| 打法 | **读页面 DOM** 拿信息，接口只用来取歌词 | **调 weapi 接口**拿信息，DOM 只用于兜底 |
| UI | 在歌曲标题后塞 3 个红按钮 | 在每个页面塞十几个大按钮 + SweetAlert 弹窗 |
| 强项 | 轻、直观、封面/歌词一键看 | 批量下载、多音质、云盘快传、元数据 |
| 弱项 | 只能单曲；歌单靠 DOM 表格（改版就废） | 改得原生页面面目全非；4 个 CDN 依赖 |

**合并的基本原则**：B 的接口能力 + A 的"一眼可见"体验，用**侧边悬浮面板**承载，两者都不再往原生页面里塞按钮。

## 1. 重复功能怎么合的（核心）

### 1.1 下载地址 —— 两套方法都留，串成一条自动降级链

| 来源 | 原做法 | 合并后 |
|---|---|---|
| A | `GET /song/media/outer/url?id=X.mp3` → HEAD 探活 → `a[download]` | 作为**方法③ 外链直取**（最后兜底，不承诺音质） |
| B | `fee===0 && plLevel<dlLevel` 时用 `/song/enhance/download/url/v1`，否则 `/song/enhance/player/url/v1` | 拆成**方法① 增强下载接口** 与 **方法② 试听播放接口** |

合并后的顺序（可在设置里单独开关）：

```
请求音质 jymaster
 ├─ 方法① 增强下载接口 ── 无地址（匿名/无权限）──▶ 记录 tried
 ├─ 方法② 试听播放接口 ── 有地址，但实际是 exhigh ──▶ 记为 best（不冒充 jymaster）
 ├─ 方法③ 外链直取 ── 302 到 m701.music.126.net ──▶ 音质未知，不参与"更好"比较
 └─ 本档结束：已有 best → 停止降档，返回 exhigh 并标记 downgraded
```

补充规则：

- **`自动降档`**（默认开）：当前档拿不到就试下一档，最多到 standard；
- **`仅目标音质`**（默认关）：只要不一致就跳过，不做任何妥协；
- **某一档拿到地址就停止降档**：再往下只会更低，不做无意义请求（每首歌最坏 3 次请求）；
- **三种方法全关时**明确报"未启用任何取链方式"，不会静默失败；
- 实际用了哪条方法、实际拿到哪一档，**都会写在提示里**（"已保存 · 极高 · 试听播放接口（已降档，实际 极高）"）。

> 实测（`logs\net-probe.json`）：匿名态下方法① 恒空、方法② 可用（返回的是被封顶的 exhigh）、方法③ 能 302 到真文件。
> 这正是你说的"第一个失败自动试第二个"的现实价值 —— 不是冗余设计，是**唯一能下的路**。

### 1.2 歌曲/歌单信息 —— 接口优先，DOM 兜底

| 场景 | A | B | 合并后 |
|---|---|---|---|
| 单曲信息 | 从 URL 取 id，标题读 `.tit` | `/api/v3/song/detail` | **接口**（`Api.songDetail`），失败时回落到标题 DOM |
| 歌单曲目 | 读 `#g_iframe` 的 `tbody.rows` 拼 id/标题/歌手 | `/api/v6/playlist/detail` + 分批 `v3/song/detail` | **接口**（完整列表、带音质与云盘标记），DOM 只作为"这是歌单页"的判断依据 |
| 封面 | 猜 `img[src*="music.126.net"]` | `song.al.picUrl` | **接口优先**，`picUrl` 为空时退回 A 的 DOM 猜法（保留备用方法） |
| 正在播放 | 无 | 无（各自另开入口） | 新增：优先 `window.player.getPlaying()`，再退 `.m-playbar` 链接 |

### 1.3 歌词 —— 只留一份解析，展示方式重做

| | A | B | 合并后 |
|---|---|---|---|
| 请求 | `/api/song/lyric?id=&lv=1&kv=1&tv=-1`（明文接口） | `/api/song/lyric/v1`（weapi，一次拿 lrc/tlyric/romalrc/yrc） | **v1 接口**（一次拿全） |
| 解析 | 无（原样打印） | `parseLyric` + 二分插入合并 | 重写为"时间戳→译文"映射合并（同样对齐、但不再依赖二分插入的边界特例） |
| 展示 | **弹一个新窗口** document.write | 无独立展示（只写进标签） | 面板内嵌预览 + 另存 `.lrc`/`.txt`；不再开窗口 |

`合并翻译` / `合并罗马音` 做成开关（默认只合并翻译）。合并结果长这样：

```
[00:01.00]故事的小黄花 / The little yellow flower
```

### 1.4 元数据与封面落盘 —— 去掉 mp3tag.js，自己写 ID3v2.4

| | A | B | 合并后 |
|---|---|---|---|
| 依赖 | 无 | `mp3tag.js` + 自写 `MetaFlac` + Vorbis comment（约 500 行） | **自写 ID3v2.4**（约 120 行，零依赖） |
| MP3 | 不写 | 写 title/artist/album/cover/lyric | 写 `TIT2/TPE1/TPE2/TALB/TRCK/TPOS/TDRC/APIC/USLT`，写入前先剥掉旧标签 |
| FLAC | — | 写 Vorbis comment + PICTURE | **只旁挂 `.jpg` + `.lrc`**（不动 FLAC 块结构，宁可少写也不写坏） |

> 这是唯一一处"能力缩水"的取舍，理由写在 README 的已知限制里。

### 1.5 界面 —— 三套 UI 收敛成一套

| 原形态 | 处理 |
|---|---|
| A：`.tit` 后 3 个红色小按钮（16px，挤在标题里） | 删除。功能进面板「单曲」页 |
| B：每页十几个 `swal2-styled` 大按钮，散落在页面各处 | 删除。入口统一为右下角 48px 圆球 |
| A：自写 toast / detail modal | 与 B 的 SweetAlert 合并为**一套** Shadow DOM 内的 toast + modal |
| B：SweetAlert2（CDN） | 去掉依赖，面板自带样式与主题 |
| 两套 `MutationObserver` + 定时器反复插按钮 | 删除。面板只挂一次，靠 `Tracker` 轮询当前对象（1.5s，只读 DOM 文本） |

## 3. 为什么这五个没搬（不是不能，是不该现在搬）

| 功能 | 原实现规模 | 不搬的理由 | v1.1 怎么补 |
|---|---|---|---|
| 云盘去重 `CloudDeduplication` | 约 540 行 + 一整套分页 UI | 会**删除云盘文件**，误判代价高（同名不同版本、伴奏/纯音乐判断）。必须先有"干跑对比表"再动手 | 先做"只列出重复组 + 建议保留哪个"，人工确认后再执行 |
| 本地文件打标签 `MusicFile` | 约 580 行 | 涉及读本地文件、多格式标签改写，与下载流程无耦合 | 独立成"工具页"的第二个入口，先只支持 mp3 |
| 云盘导入/本地上传 `LocalUpload` | 约 430 行 | 真正上传字节（分片 8MB、NOS token、转码轮询），失败面大 | 先做"上传 + 校验 md5"，不做转码等待 |
| 云盘音质提升 `Upgrader` | 约 380 行 | 会对云盘文件做批量替换，风险同上 | 与去重一起做，共用"预演 → 确认"框架 |
| 歌单排序 | 约 300 行 | **回写云端数据**，一个 bug 就把用户的歌单顺序改了 | 先在本地算出顺序、导出对照表，让用户自己决定是否回写 |

> 判断依据：这五个都是"**会改用户云端数据**"的操作。合并脚本的第一目标是"两个脚本不再打架、下载这条路走通"，
> 把不可逆操作塞进第一版不划算。它们需要的代码量差不多等于现在整个 v1.0。

## 4. 顺手修掉的原脚本问题

| 原脚本的问题 | 现在 |
|---|---|
| A 每 3 秒 `setInterval` + 全 body `MutationObserver` 反复插按钮（长期占 CPU） | 只挂一次面板；`Tracker` 1.5s 只读几个节点文本/href |
| A 用 `document.write` 打开歌词窗口（部分浏览器会吞掉脚本/触发 Trusted Types 警告） | 面板内渲染，无 `document.write` |
| A 的下载 `a.click()` 会被网易云 SPA 的全局点击监听劫持（原作者自己加了 `stopImmediatePropagation` 补丁） | 保留该补丁，并统一到一个 `saveBytes` 里（所有下载都走同一条路） |
| B 依赖 4 个 CDN（SweetAlert2 / ajax-hook / node-forge / mp3tag），断网或 jsDelivr 抽风就整个脚本不可用 | **零外部依赖**（WebCrypto + BigInt + 自写 ID3 + 自绘 UI） |
| B 在 `document-start` 用 ajax-hook 全局劫持 `fetch`/`XHR`，改页面播放请求 | 不做全局劫持；试听走自己的接口调用 |
| B 的请求头方案曾把网页 cookie 清掉（作者自己加了警告弹窗） | 不碰用户 cookie；只在需要时给请求附加客户端头 |
| 两个脚本都会往 `.tit` 塞元素，互相覆盖/错位 | 面板在 Shadow DOM，与页面零争用 |
