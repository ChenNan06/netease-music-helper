# 操作逻辑与设置

> 为什么面板长这样、每个按钮为什么放在那儿、每个设置项影响什么。
> 目标是"**像一个成熟产品**"：用户不需要记住两个脚本各自在哪，只需要知道"我现在对什么操作"。

---

## 1. 信息架构：一句话说清"当前对象"

面板顶上那张卡片（封面 + 曲名 + 歌手 + 音质徽章）是**唯一**的操作对象，右侧的标签写着来源：

| 来源 | 什么时候 | 例子 |
|---|---|---|
| `页面歌曲` | 当前 URL 是 `/song?id=xxx` 或 `#/song?id=xxx` | 你在看「晴天」的详情页 |
| `正在播放` | 其它页面，取播放栏当前曲目 | 你在歌单页听歌 |

判定顺序**就是优先级**：你在看某首歌的详情页 → 面板操作它；在歌单页 → 操作正在播放的那首。
这条规则解决的是原脚本最让人困惑的问题：**A 的按钮只认页面、B 的按钮认播放栏，于是同一个页面两个脚本给你两种答案。**

「列表」页同理：`ListSource.detect()` 先判断当前页是歌单/专辑/歌手/搜索，只有这四类页面才点亮「读取列表」。
换页时旧列表**立即作废**（避免"以为在下 A 歌单，其实下的是 B"）。

## 2. 面板结构（v1.2.0 重排后）

```
┌───────────────────────────────────────────┐
│ ♪ 网易云助手 v1.2.0            ⚙    —     │  ← ⚙ 新标签开设置页 / — 收起
├───────────────────────────────────────────┤
│ [封面] Hope                       ⏮ ▶ ⏭  │  ← 卡片 = 播放控制台：左=当前对象，右=图标控制
│        Silversun Pickups · 无损 详情页     │  ← 徽章：音质 / 云盘 / VIP / 来源
│ ⇄ 正在播放  真实                          │  ← 另有别的歌可切时才出现，整行可点
├───────────────────────────────────────────┤
│ ＋ 粘贴 ID 或链接载入…                    │  ← 载入条：收起一行，点开变 textarea
├───────────────────────────────────────────┤
│  单曲  │  列表  │  云盘  │  工具           │  ← 4 个标签，记住上次停留
├───────────────────────────────────────────┤
│ 音质 [极高 ▾]            极高·自动降档·已登录│  ← 权威值就地回显，长解释在 title 里
│ [下载歌曲][保存歌词][保存封面][云盘快传]    │  ← 主操作 = 实心红
│ 查看歌词 · 音源探测 · 复制ID · 复制链接     │  ← 次操作 = 文字链接（不再是描边按钮）
├───────────────────────────────────────────┤
│ 就绪                                      │  ← 状态栏：永远告诉你"正在干什么"
└───────────────────────────────────────────┘
```

**v1.2.0 为什么这么排**（上一版被吐槽"又丑又乱、错位、信息密度太高"）：

| 问题 | 上一版 | 现在 |
|---|---|---|
| 卡片被挤爆、标题截成 `Ho…` | 控制条、三个来源 chip 全塞进 `.meta` 里 | 改成 **grid 三列**（封面 / 文本 / 图标），控制只占右侧 82px，标题拿到 196px |
| 播放器按钮又大又是文字 | `⏮ 上一首 ⏯ 播放暂停 下一首 ⏭` 三颗大按钮 | 三个 **26px 图标按钮**（SVG），不发亮不抢视线 |
| 来源切换"傻气" | 并列 `自动 / 页面歌曲 / 正在播放` 三颗 chip + 单独一行"正在播放 XX 跟着它" | **只有一个 `⇄` 细条**：只在"另有别的歌"时出现，点它就过去；卡片上的来源徽章直接说明现在是谁 |
| 载入入口的位置 | 塞在「列表」页顶部（莫名其妙的归属） | **独立载入条，在标签页之上**，不隶属任何标签；收起时只占一行 |
| 信息密度 | 单曲页 9 个按钮 + 内联日志 6 行 | 4 个主按钮 + 一排文字链接 + **内联日志移除**（日志在「工具 → 诊断」看） |
| 载入反馈弱 | 只有左下角一行灰字 | **卡片高亮闪一下 + toast 报曲名 + 状态栏**，三处同时给反馈 |

设计约束（不变）：

- **右下角 48px 圆球**是唯一常驻入口，可拖动（记住位置），点击开/合；有绿色小点表示已就绪。
- **Shadow DOM**：面板 CSS 与站点彻底隔离，站点改版也不会把面板挤歪。
- **贴球定位**：用真实 `getBoundingClientRect` 计算，间隙固定 10px，`ResizeObserver` 跟随内容变化。
- **深浅色**：默认跟随网易云的 `night` 类；设置里可强制浅/深。

## 3. 为什么要"设置页另开标签"

面板只有 372px 宽，30 个设置项塞进去会变成滚动地狱（原脚本就是拿一叠 SweetAlert 弹窗硬塞，点三层才改得动一个音质）。
所以分工：

| 在哪 | 放什么 |
|---|---|
| **面板** | 高频、当下就要用的：音质选择、下载/歌词/封面/快传、批量入口、音源探测 |
| **设置页（新标签）** | 低频、需要想一想的：默认音质、命名模板、目录结构、并发、元数据行为、取链方法开关、请求身份、导入导出 |

设置页特性：

- 左侧 6 个分区导航，右侧卡片式表单，**改完即存**（右下角提示"已保存 12:34:56"）；
- 顶栏显示实时状态：版本 / 是否登录 / 当前对象 / 脚本管理器；
- 「数据」区：运行诊断、导出设置 JSON、导入设置、恢复默认、关闭页面；
- **双向同步**：面板里改了音质，设置页会跟着变；设置页改了，面板立即重绘（`storage` 事件 + `postMessage` 双保险）。

> 弹窗被浏览器拦截时不会静默失败：面板会提示"请允许 music.163.com 弹出窗口"，其余功能照常。

## 4. 每个设置项影响什么

### 通用
| 项 | 默认 | 影响 |
|---|---|---|
| 主题 | 跟随网易云 | `auto` 读站点的 `night` 类；`light`/`dark` 强制 |

### 下载
| 项 | 默认 | 影响 |
|---|---|---|
| 默认音质 | 超清母带 | 面板音质下拉的初始值；也是批量下载的目标音质 |
| 自动降档 | 开 | 目标音质拿不到地址时，逐档往下试（最到 standard）。**关掉后只在目标档找** |
| 仅目标音质 | 关 | 只要不一致就跳过（与自动降档互斥；用来"只要母带，没有就跳过"） |
| 文件名模板 | `{artist} - {title}` | 占位符：`{artist}{title}{album}{index}{id}{alias}`；非法字符会被替换 |
| 目录结构 | 不建目录 | `歌手/` 或 `歌手/专辑/`（写进下载路径） |
| 批量并发 | 4 | 1–8。越高越快也越容易被风控；每首歌内部还是串行取链 |
| 写入 MP3 标签 | 开 | 标题/歌手/专辑/音轨/年份 + 内嵌封面 + 内嵌歌词（仅 mp3） |
| 另存封面文件 | 开 | 单曲存 `{同名}.jpg`；批量在有目录时每个专辑目录存一次 |
| 另存歌词文件 | 开 | `{同名}.lrc`（或 `.txt`，看歌词格式设置） |
| 跳过云盘已有 | 关 | 批量时凡 `privilege.cs=true` 的曲目直接跳过 |
| 方法①/②/③ | 全开 | 取链顺序固定 ①→②→③，这里只是开关。**全关会直接报错**，不会静默 |

### 歌词
| 项 | 默认 | 影响 |
|---|---|---|
| 合并翻译 | 开 | 译文接在同一时间轴之后：`原文 / 译文` |
| 合并罗马音 | 关 | 同上（与翻译叠加时顺序是 原文 / 译文 / 罗马音） |
| 保存格式 | LRC | LRC 带时间轴；TXT 只有文字 |

### 云盘
| 项 | 默认 | 影响 |
|---|---|---|
| 快传后自动关联曲库 | 开 | 关掉只是"文件进云盘"，歌曲仍显示为未拥有 |

### 网络
| 项 | 默认 | 影响 |
|---|---|---|
| 请求间隔 | 120ms | 两次接口调用之间的最小间隔；批量时调的太猛容易触发风控 |
| 失败重试 | 1 | 网络抖动时自动重试次数 |
| 请求身份 | 网页 | 见 `docs/接口与实测.md` 的身份表 |
| 自定义 UA | 空 | 留空用默认；填了会覆盖身份 UA |
| 记录接口日志 | 关 | 打开后控制台打印每个接口的 code 与入参（排错用） |

## 5. 关键交互决策（和原脚本对比）

| 场景 | 原脚本 | 现在 | 为什么 |
|---|---|---|---|
| 下载失败 | 弹一个 alert 或者什么都不说 | 状态栏 + toast + 日志都写明原因（"无可用下载地址"/"保存失败:xxx"），批量结束还会列出失败明细 | 失败必须可解释，否则用户只能反复试 |
| 音质不一致 | 静默给低音质，标签还写母带 | 明确标"已降档，实际 极高" | 不冒充 |
| 批量 100 首 | 表格式进度表（SweetAlert 里塞 `<table>`） | 一根进度条 + `成功/失败/速率` + 可停止 | 面板宽度有限，表格在 372px 里没法看 |
| 云盘删除 | 直接删 | **二次确认**，写清"将删除 N 个文件，网易云侧不可撤销" | 不可逆操作 |
| 看歌词 | 新开一个窗口 | 面板内滚动预览 | 少一个窗口，且和"保存歌词"在同一个上下文 |
| 查看封面 | 鼠标悬停出大图（跟光标跑） | 点封面放大（点击遮罩关闭） | 面板里没有"光标位置"这个概念 |
| 复制 ID/链接 | 无 | 有 | 分享/排错时最常用 |
| 诊断 | 无 | 一键输出：登录态、三路取链实测、云盘码、日志 | 接口一变，先看这个 |

## 6. 边界与异常（都实测过）

| 情况 | 行为 |
|---|---|
| 未登录 | 单曲下载仍可用（走方法②③）；云盘相关明确提示"需要登录"；`诊断` 里显示未登录 |
| 歌曲无版权（`privilege.st<0`） | 取链全空 → 失败原因"所有取链方式均未取到地址" |
| 纯音乐（`pureMusic`） | 不写歌词、不存歌词文件，提示"这首歌没有歌词" |
| 换页 | 旧列表作废、重新识别当前对象（防串台） |
| 面板被拦弹窗 | 设置页打不开时给提示，其余功能不受影响 |
| 批量中途想停 | 「停止」按钮置 `Job.cancelled`，进行中的请求会完成、后续任务不再取 |
| 批量时浏览器拦多文件下载 | 确认框里提前写明"可能弹一次允许"，点允许即可 |
| 接口改版 / 风控 | 三路取链会有一路先失效，`诊断` 能立刻看出是哪一路 |

## 7. 一次典型操作（完整时序）

```
用户打开 /song?id=186016
  └─ Tracker（1.5s 轮询 + hashchange）→ resolveTarget() → {id:186016, source:'页面歌曲'}
     └─ Api.songDetail → normalizeSong → 卡片渲染（音质徽章 = privilege.plLevel）
用户点「下载歌曲」
  └─ downloadSong(song)
     ├─ resolveSongUrl: ① 增强下载 → 空 → ② 试听 → 有（exhigh）→ 停止降档
     ├─ getLyric（因为开了"写入标签"/"另存歌词"）→ 合并翻译
     ├─ fetchBinary(封面 500×500)
     ├─ fetchBinary(音频) → stripId3 → buildId3Tag(TIT2/TPE1/TALB/APIC/USLT) → 拼接
     └─ saveBytes → <a download>（带 SPA 劫持补丁）→ 落盘
  └─ 状态栏：下载完成：周杰伦 - 晴天.mp3
     toast：已保存 · 极高 · 试听播放接口 · 已降档
```

## 8. v1.0.1 补的三处（都是实测反馈）

### 8.1 「当前生效」提示行：把"显示值"和"实际值"合到一个来源

音质下拉下面固定一行小字：

```
当前生效：超清母带（无权限时自动降档） · 未登录
```

它**直接读存储**（`Store.settings.quality`），不受下拉框渲染时序影响。
每次 `renderBody()` 结束都会跑一次 `syncControls()`，把 `<select>` 的值强制对齐存储 ——
即使某次渲染漏了，下一次渲染也会自愈。设置页那边加了 `dirty` 标记：你正在改的时候，
主面板回推的值不会覆盖你的输入；切回设置页标签时会主动拉一次最新值。

### 8.2 面板贴球：用真实高度，不用估算

```
间隙 GAP = 10px
球在下半屏 → 面板底边 = 球顶 - 10px
球在上半屏 → 面板顶边 = 球底 + 10px
可用空间不够（< 260px）→ 自动换到另一侧
maxHeight  = 真实可用空间（球到视口边缘），最小 220px
宽度       = min(372, 视口宽 - 16)
```

关键点是**先量自然高度再定位**（旧版用 `min(78vh,720)` 估算，面板实际 400 多高 → 底边离球几百像素），
再用 `ResizeObserver` 监听尺寸变化 → 日志/歌词让面板变长时**立刻重新贴合**，永远不会盖住球。

### 8.3 「导出登录态」：仅开发版，发布版会整段剥离

面板「工具」页底部有一个按钮，导出 `ncmh-session.json`（含 `MUSIC_U` 等必要 cookie）。
用途只有一个：让 AI 在本机能复现"登录后才有的行为"（高音质取链、云盘快传、歌单全量）。

- **为什么之前失败**：`MUSIC_U` 是 **HttpOnly** cookie，`document.cookie` 读不到 → 旧实现既误判登录态，也让导出必然失败。
  现在优先走 `GM_cookie`（管理器能读 HttpOnly），读不到就给 F12 手动复制的指引。
- **发布版没有它**：构建时 `--release` 会把 `// #region dev-only` 整段剥掉，并删掉 `@grant GM_cookie`，
  由 18 项构建门禁验证"剥干净且还能跑"。所以 GitHub 上的版本是干净的。

## 9. 登录态判定（v1.0.2 的重要修正）

```
旧：document.cookie 里有 MUSIC_U → 已登录     ← 错！HttpOnly，永远读不到
新：GET /weapi/w/nuser/account/get
      profile != null → 已登录（顺便拿到昵称与 VIP 类型）
      profile == null → 未登录（实测匿名返回 {code:200, account:null, profile:null}，无副作用）
      接口异常       → 保持原状态 + 记录原因（不武断判成未登录）
```

- 结果缓存 60 秒，`重新检测登录` 可强制刷新；
- 面板徽章、「当前生效」提示行、设置页顶栏、诊断输出**全部读同一个 `Login` 状态**；
- 云盘相关操作前会 `await Login.ensure()`，未登录时明确提示"云盘属于账号，请先登录"，而不是让人以为脚本坏了。

## 10. 音源探测（替代被删掉的试听器）

点「单曲 → 音源探测」：**不播放、不下载**，只把结果摊开。
| 结果 | 面板显示 |
|---|---|
| 可用 | 实际音质（含"已降档"标注）、取到地址的通道、文件大小 |
| 不可用 | 原因 + **逐路明细**（`增强下载接口/母带:无  试听播放接口/母带:无 …`） |

为什么删试听器：它调的是**和下载同一个接口**，能播就一定能下，播不了也不代表下不了（下载有三路降级）。
而 `audio.play()` 前面有 `await`，用户手势上下文已丢失，浏览器会静默拦截自动播放 —— 这就是"无法完整运行"的根源。
判断"这首歌能不能下"应该用探测（看接口结果），而不是用播放器（看浏览器脸色）。

## 11. v1.1.0：输入、列表交互、目标切换（这三个是联动的）

### 11.1 载入：一个入口，落在最合适的地方

**载入条在标签页之上**（不属于任何标签页），收起时就是一行虚线提示，点开变 textarea。支持**混着贴**：

```
186016
https://music.163.com/#/song?id=186016
https://music.163.com/playlist?id=3778678
https://music.163.com/album?id=32311
```

识别规则（`parseRefs`，纯函数，有单测）：

| 输入形态 | 解析结果 |
|---|---|
| 纯数字（3~12 位） | 歌曲 ID |
| 含 `song?id=` 或 `/song/123` | 歌曲 |
| 含 `playlist/album/artist/toplist?id=` 或 `/playlist/123` | 对应列表（**优先级高于歌曲**，否则 `playlist?id=` 会被误判成歌曲） |
| 其它 | 进 `unknown`，不当 id 猜 |

**落点由数量决定（这是关键的操作逻辑）**：

| 解析结果 | 行为 |
|---|---|
| 1 首 | **直接载入单曲卡片**并切到「单曲」页 —— 因为下一步必然是在这张卡片上点下载 |
| 多首 / 含列表链接 | 生成一个「手动列表」，停在「列表」页 —— 因为下一步必然是勾选/翻页/批量 |
| 重复 id | 自动去重 |

反馈是三处同时给的：**卡片高亮闪一下 + toast 报曲名 + 状态栏文字**，解析完自动收起输入条。

### 11.2 列表：从"只能看"变成"能操作"

| 能力 | 说明 |
|---|---|
| 翻页 | 每页 20 / 50 / 100 / 500，改完记住（`listPageSize`）；页脚显示 `3 / 12　共 231 首` |
| 搜索 | 作用于**全量**（不只是当前页），匹配歌名/歌手/专辑/别名；只重画行，**不打断输入焦点** |
| 勾选 | 每行复选框；「全选本页」「清空选择」；**选中状态跨页保持** |
| 单首操作 | 行尾 `⤓` 直接下这一首；点行其它区域 = 把这首设为当前对象并跳到单曲页（可看歌词/快传/探测） |
| 批量 | 按钮文字随选择变化：「下载选中(N)」/「批量下载全部」；**未勾选时以筛选结果为准**，确认框写明范围（例：`将下载《热歌榜》全部 200 首`） |
| 导出 | TXT/CSV/JSON 同样遵循"选中优先，否则筛选后全部" |

### 11.3 目标切换：一条细提示，三项循环（v1.3.0）

曾经摆过 `自动 / 页面歌曲 / 正在播放` 三颗 chip 外加"跟着它"按钮——用户原话"很傻气"。现在只有一个控件：

| 情况 | 卡片显示 |
|---|---|
| 只有一种来源 | 不出现任何切换提示 |
| 有两种以上 | 底部一行 `⇄ 载入歌曲  歌6` / `⇄ 详情页  186016` / `⇄ 正在播放  真实` |
| 点它 | **在三项之间循环**：载入歌曲 → 详情页 → 正在播放 → 载入歌曲… |

要点：

- **不暴露"模式"**：只有"⇄ 去那首"，点一次换一个；顺序按当前对象旋转，保证每次点都真的换到另一首；
- 切到「详情页」也是**面板自己拉数据**（`Api.songDetail`），**不跳转页面**；
- 一行 11px 灰字 + 虚线上边，不占按钮位；
- 卡片上的来源徽章（`链接载入` / `列表选择` / `详情页` / `正在播放`）说明"现在这张卡是谁"。

**pin 机制（为什么载入的歌不会被抢）**：

```
手动载入 / 列表点选 → pin = {id, name, source, pageAt: 当前页面歌曲 id}，mode='pinned'
auto 模式下 pin 优先 → 页面歌曲抢不走
解除条件只有一个：页面导航到了另一首歌（pageId ≠ pin.pageAt）
```

这样"在同一个页面上载入一首歌"很稳，而"翻到别的歌的详情页"仍然照常跟着页面走。

**▶ 的语义随上下文变**（v1.3.0）：

| 卡片状态 | ▶ 做什么 |
|---|---|
| 卡片 = 正在播放 | 控制网页播放器的播放/暂停 |
| 卡片 ≠ 正在播放 | **播放这首**：依次试 `player.playById` → `player.send('/api/song/play')` → top/iframe 内同名对象 → 页面 `<audio>` 直连 |

走直连通道时 toast 会注明"网页播放条可能不跟随"，不装作一切正常。

播放控制收敛成 **三个 26px 图标按钮**（`⏮ ▶ ⏭`），找不到原生按钮时**整条不显示**（不给点不动的东西）。

## 12. 底部极简进度条（v1.3.0）

位置：状态栏上方，2px 高，颜色用主色 `#EC4141`。

| 状态 | 表现 |
|---|---|
| 单曲取字节 / 解析链接 | 不确定态（一段 38% 宽的滑块来回跑），因为拿不到真实百分比 |
| 批量下载 / 快传 | 真实百分比（`done/total`），由 `setProgress()` 统一驱动 |
| 完成 | 100% 后停 1.2 秒自动收起 |
| 失败 / 取消 | 立即收起（不把失败伪装成进度） |

设计约束：**只在"确实有进度"时出现**，静止时不占视觉；不弹窗、不在正文堆进度文字。

## 13. 云盘到底是干什么的（很多人第一次都会问）

**云盘 = 网易云给你的"私人音乐仓库"**（网页版首页左侧「我的音乐云盘」）。它和"下载到本地"是两件事：

| | 云盘 | 下载到本地 |
|---|---|---|
| 歌存在哪 | 网易云账号里（云端） | 你的硬盘 |
| 手机/网页/车机能听吗 | **能，任何登录该账号的设备** | 不能，只在你存的那台设备 |
| 受版权下架影响吗 | **不受**（已在你云盘里的歌，下架后仍能播） | 不受 |
| 容量 | 有上限（按账号等级，通常几 GB~几十 GB） | 硬盘大小 |

所以云盘的三个真实用途：

1. **保命**：把歌单里的歌"存进云盘"，哪天版权下架/变成 VIP 独占，你云盘里那份还能听；
2. **跨设备**：不占手机空间，登录就能听；
3. **塞自己有的东西**：本地稀有音频/现场版/翻唱传上去，网易云就变成你的播放器。

而**「快传」是云盘最省事的上传方式**：它不上传音频字节，只提交文件的 **md5 + 元信息**；服务器上若已有同一份文件（网易云曲库里绝大部分都有），直接"认领"进你的云盘——**秒完成、零流量**。

> 顺便看了你的账号：云盘里目前**只有 1 首**（《真实》— 张惠妹 10.5MB），说明你确实没在用。
> 如果你只是"想把歌存到自己电脑上"，云盘对你价值不大，可以完全忽略这块；
> 什么时候有用：你想在**手机/别的电脑**上听某些"已经下架或要 VIP"的歌，或者想把本地文件塞进网易云一起管理。
